# Skill: fluxcd-setup

# FluxCD GitOps Setup Generation

## Overview

Generate production-ready FluxCD GitOps configurations for Kubernetes clusters. This skill creates a complete, layered GitOps structure following community best practices and the patterns established by the HomeCluster and onedr0p/flux-cluster-template repositories.

**Core principle:** GitOps should be declarative, layered, and secure by default.

## When to Use

**Use this skill when:**
- Setting up a new Kubernetes cluster with FluxCD
- Migrating an existing cluster to GitOps
- Creating a home lab or production cluster
- Need a standardized, maintainable GitOps structure

**Key outcomes:**
- Layered deployment architecture (Infrastructure → Core → Operators → Apps)
- SOPS-encrypted secrets management
- Variable substitution for environment-specific configs
- Helm and OCI repository management
- Bootstrap-ready configuration

## Architecture Overview

### Layered Deployment Model

```
┌─────────────────────────────────────────────────────────────┐
│                    APPLICATIONS LAYER                        │
│         (User-facing apps, depends on Core + Infra)         │
├─────────────────────────────────────────────────────────────┤
│                    OPERATORS LAYER                           │
│    (Database operators, CRDs, depends on Core + Infra)       │
├─────────────────────────────────────────────────────────────┤
│                     CORE LAYER                               │
│   (Platform services: Auth, Registry, CI/CD, depends Infra) │
├─────────────────────────────────────────────────────────────┤
│                 INFRASTRUCTURE LAYER                         │
│      (CNI, Storage, Service Mesh, Monitoring - Base)        │
└─────────────────────────────────────────────────────────────┘
```

## Configuration Components

### 1. Bootstrap Configuration

**Location:** `clusters/<cluster-name>/flux-system/`

**Files:**
- `gotk-components.yaml` - Flux CD controllers (generated by `flux install`)
- `gotk-sync.yaml` - GitRepository and root Kustomization
- `kustomization.yaml` - Kustomize patches for Flux deployment

**Example gotk-sync.yaml:**
```yaml
---
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: flux-system
  namespace: flux-system
spec:
  interval: 1m0s
  ref:
    branch: main
  secretRef:
    name: flux-system
  url: ssh://git@github.com/<owner>/<repo>
---
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: flux-system
  namespace: flux-system
spec:
  interval: 10m0s
  path: ./clusters/<cluster-name>
  prune: true
  sourceRef:
    kind: GitRepository
    name: flux-system
```

### 2. Layer Kustomizations

**Location:** `kubernetes/flux/*.yaml`

**Pattern:** Each layer defines a Kustomization that depends on lower layers.

**Example infrastructure.yaml:**
```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: cluster-infrastructure
  namespace: flux-system
spec:
  interval: 30m
  path: ./kubernetes/infra
  prune: true
  sourceRef:
    kind: GitRepository
    name: flux-system
  decryption:
    provider: sops
    secretRef:
      name: sops-age
  postBuild:
    substituteFrom:
      - kind: ConfigMap
        name: cluster-settings
      - kind: Secret
        name: cluster-secrets
```

### 3. Helm Repositories

**Location:** `kubernetes/flux/repositories/helm/` and `oci/`

**Example HelmRepository (HTTP):**
```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: jetstack
  namespace: flux-system
spec:
  interval: 1h
  url: https://charts.jetstack.io
```

**Example HelmRepository (OCI):**
```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: bjw-s
  namespace: flux-system
spec:
  type: oci
  interval: 5m
  url: oci://ghcr.io/bjw-s/helm
```

### 4. Application Deployment Pattern

**Location:** `kubernetes/apps/<namespace>/<app>/`

**Structure:**
```
<app>/
├── ks.yaml                    # Flux Kustomization resource
└── app/
    ├── kustomization.yaml     # Kustomize configuration
    ├── helmrelease.yaml       # HelmRelease resource
    ├── secret.sops.yaml       # Encrypted secrets (optional)
    └── values.yaml            # Helm values (optional)
```

**Example ks.yaml:**
```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: &app <app-name>
  namespace: flux-system
spec:
  targetNamespace: <namespace>
  commonMetadata:
    labels:
      app.kubernetes.io/name: *app
  path: ./kubernetes/apps/<namespace>/<app>/app
  prune: true
  sourceRef:
    kind: GitRepository
    name: flux-system
  wait: true
  interval: 30m
  retryInterval: 1m
  timeout: 5m
```

**Example helmrelease.yaml:**
```yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: <app-name>
  namespace: <namespace>
spec:
  interval: 30m
  chart:
    spec:
      chart: <chart-name>
      version: "x.y.z"
      sourceRef:
        kind: HelmRepository
        name: <repo-name>
        namespace: flux-system
  maxHistory: 2
  install:
    remediation:
      retries: 3
  upgrade:
    cleanupOnFail: true
    remediation:
      retries: 3
  uninstall:
    keepHistory: false
  values:
    # Chart values here
```

### 5. Secrets Management (SOPS)

**Location:** `.sops.yaml` (root) and `*.sops.yaml` files

**Example .sops.yaml:**
```yaml
---
creation_rules:
  - path_regex: kubernetes/.*\.sops\.ya?ml
    encrypted_regex: ^(data|stringData)$
    key_groups:
      - age: [<age-public-key>]
```

**Example encrypted secret:**
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: <secret-name>
  namespace: <namespace>
stringData:
  password: ENC[AES256_GCM,data:...,iv:...,tag:...,type:str]
sops:
  age:
    - recipient: <age-public-key>
      enc: ...
  lastmodified: "2024-01-01T00:00:00Z"
  version: 3.8.1
```

### 6. Variable Substitution

**Location:** `kubernetes/flux/vars/`

**Cluster Settings (ConfigMap):**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: cluster-settings
  namespace: flux-system
data:
  TIMEZONE: America/New_York
  CLUSTER_DOMAIN: cluster.local
  INGRESS_CLASS: nginx
```

**Usage in manifests:**
```yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: my-app
spec:
  values:
    config:
      timezone: ${TIMEZONE}
      domain: ${CLUSTER_DOMAIN}
```

## Bootstrap Process

### Prerequisites

1. Kubernetes cluster (k3s, Talos, kubeadm, etc.)
2. `flux` CLI installed
3. `sops` and `age` for secrets
4. `kubectl` configured

### Bootstrap Steps

1. **Generate Age Key:**
   ```bash
   age-keygen -o age.key
   ```

2. **Create SOPS Config:**
   Update `.sops.yaml` with the public key from `age.key`

3. **Bootstrap Flux:**
   ```bash
   # Using flux CLI
   flux bootstrap github \
     --owner=<github-username> \
     --repository=<repo-name> \
     --branch=main \
     --path=clusters/<cluster-name> \
     --personal
   
   # Or manually apply
   kubectl apply --kustomize ./kubernetes/bootstrap
   kubectl create secret generic sops-age \
     --namespace=flux-system \
     --from-file=age.agekey=./age.key
   ```

4. **Apply Cluster Configuration:**
   ```bash
   kubectl apply --kustomize ./kubernetes/flux/config
   ```

## Best Practices

### Layer Dependencies

```
Infrastructure (no deps)
    ├── Core (depends on Infrastructure)
    ├── Operators (depends on Core + Infrastructure)
    └── Apps (depends on Core + Infrastructure)
```

### Reconciliation Intervals

- **Infrastructure:** 30m (stable components)
- **Applications:** 15-30m (frequent updates)
- **Repositories:** 1h (chart updates)
- **Secrets:** 1h (security-sensitive)

### Security

1. **Encrypt all secrets** with SOPS + Age
2. **Use NetworkPolicies** to restrict Flux controller access
3. **Enable RBAC** with least privilege
4. **Rotate credentials** regularly
5. **Audit changes** via Git history

### Naming Conventions

- **Kustomizations:** `cluster-<layer>` (e.g., `cluster-infrastructure`)
- **HelmReleases:** `<app-name>` (e.g., `cilium`, `cert-manager`)
- **Namespaces:** `<purpose>-system` (e.g., `monitoring-system`)
- **Secrets:** `<app>-secret` or `<purpose>-secrets`

### Common Helm Repositories

| Repository | URL | Purpose |
|------------|-----|---------|
| bitnami | https://charts.bitnami.com/bitnami | Common apps |
| jetstack | https://charts.jetstack.io | cert-manager |
| cilium | https://helm.cilium.io | CNI |

## Troubleshooting

### Check Flux Status
```bash
flux get all
flux get kustomizations
flux get helmreleases
```

### Force Reconciliation
```bash
flux reconcile source git flux-system
flux reconcile kustomization cluster
```

### Debug Kustomization
```bash
flux build kustomization <name> --path ./kubernetes/<layer>
kubectl describe kustomization <name> -n flux-system
```

### Check Logs
```bash
kubectl logs -n flux-system deployment/kustomize-controller
kubectl logs -n flux-system deployment/helm-controller
kubectl logs -n flux-system deployment/source-controller
```
