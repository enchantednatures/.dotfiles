Create a comprehensive specification and PRD

You are helping create a specification for a new feature or project. Follow the `specify` skill methodology to create a thorough PRD.

## Context

The user wants to create a specification. You need to:
1. Ask clarifying questions to understand intent
2. Draft a comprehensive PRD
3. Review for completeness

## Process

### Step 1: Understand Requirements

Ask questions to clarify:
- Who is the user?
- What problem are we solving?
- What does success look like?
- What are the constraints?
- What integrations are needed?

### Step 2: Draft the PRD

Create a PRD with:
- Overview and goals
- User stories
- Functional requirements (Given/When/Then)
- API/interface specifications
- Technical constraints
- Acceptance criteria

### Step 3: Validate Completeness

Check for:
- All requirements have acceptance criteria
- Edge cases documented
- Performance/security addressed
- Dependencies identified

## Output Format

Save the PRD to a file:
- Path: `specs/YYYYMMDD-feature-name.md`
- Format: Markdown with structure from `specify` skill

## Response Structure

1. Summary of what you understood
2. The drafted PRD
3. Any open questions
4. Location where PRD was saved
